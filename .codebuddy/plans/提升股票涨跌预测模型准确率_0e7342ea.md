## User Requirements

- 提升 `AkShareDemo.py` 当前 47.8% 的模型测试集准确率，并让评估结果更可信、更有参考价值。
- 继续使用腾讯行情接口，不重新引入已限流的东方财富接口。
- 保留现有 Streamlit 页面结构与交互方式，仅在模型分析区域增加必要诊断信息。

## Product Overview

股票分析页面的“模型分析”区域将从单一准确率展示升级为可解释的评估结果。用户可调整回看年限、标签阈值与模型选项，页面输出更稳定的准确率、F1、AUC、混淆矩阵、多数类基线和次日涨跌预测。

## Core Features

- 增加基于历史数据的相对收益、均线距离、波动率、成交量变化等技术指标。
- 提供时间序列切分与交叉验证评估，避免随机打乱造成的数据泄漏。
- 支持标签阈值设置，过滤波动过小带来的噪声标签。
- 对比多种轻量模型并自动选择验证表现最佳者。
- 展示准确率之外的评估指标、类别分布与基线参考。
- 保留数据缓存、股票名称显示、K线与均线图表。

## Implementation Approach

先修正标签与评估口径，再增强特征与模型，避免只调参导致虚假提升。核心策略是把数据获取、特征工程、标签生成、模型评估和界面展示拆成可测试函数，并在全部环节禁止未来信息泄漏。

关键决策：

- 继续用 `ak.stock_zh_a_hist_tx`，因为东方财富 push2 已出现 IP 限流；腾讯接口当前无显式限流标识。
- 标签仍以次日涨跌为核心，但增加阈值参数，把“微小涨跌”从噪声中区分出来。
- 用时间序列切分替代单次固定切分，并用 `TimeSeriesSplit` 在训练集内做模型选择，降低单次 48 条测试样本带来的波动。
- 用相对收益与比率特征替代原始价格作为主要输入，减少不同价格区间带来的伪相关。
- 模型对比限定在 scikit-learn 内置轻量模型：随机森林、逻辑回归、直方图梯度提升；自动选优以验证集 F1 或 AUC 为主，而非单一 accuracy。

性能与可靠性：

- 特征工程复杂度为 O(n*w)，n 为交易日数，w 为最大滚动窗口，默认不超过 60；千级样本下开销可忽略。
- 模型评估复杂度约为 O(k*f*n log n)，k 为候选模型数，f 为折数，控制在小网格与 3 到 5 折内。
- 保留 `load_data` 的 `@st.cache_data(ttl=3600)`，避免页面刷新重复请求行情接口。

## Implementation Notes

- 修复当前标签缺陷：`shift(-1)` 在最后一行会产生 NaN，当前 `np.where` 会把最后一行错误标为下跌；必须显式删除最后一条无次日价格的样本。
- 所有滚动指标只使用当前及历史数据，标签在特征生成后单独计算，防止未来收盘价进入特征。
- 增加最小样本量保护：少于 60 条或切分后任一类样本过少时，用 `st.warning` 提示并跳过训练。
- 处理单类别、空数据、接口异常，保持现有 `try/except` 与 `st.error` 风格；不要把大量行情数据写入日志。
- 保留现有默认股票 `600519`、默认近 365 天和现有图表，新增控件放在侧边栏或可折叠区域，降低界面改动幅度。
- 预测时需要复用同一套特征生成逻辑，并只传入特征列，避免把标签列或日期索引误作为模型输入。
- 恢复东方财富接口不在本次范围内，避免再次触发限流。
